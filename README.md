## Четвертый чекпоинт

### Серверная реализация

Серверная часть проекта разрабатывается в ветке `dev/feature/service`. В корневой директории находится папка `lambdas`, в которой каждая подпапка соответствует отдельной AWS Lambda-функции. Деплой лямбд осуществляется посредством GitHub Actions с автоматизацией следующих этапов:

1. **Сборка Docker-образа:** При запуске пайплайна для конкретной лямбды инициируется сборка Docker-образа на основе подготовленного Dockerfile.
2. **Публикация в Amazon ECR:** После успешной сборки образ автоматически отправляется в соответствующий репозиторий в Amazon ECR, что обеспечивает централизованное хранение и версионирование.
3. **Обновление AWS Lambda:** После публикации GitHub Actions инициирует процесс обновления конфигурации AWS Lambda-функции, переводя её на новый Docker-образ.

#### Механизм деплоя по веткам

Новые версии деплоятся при выполнении merge pull request. При этом реализована логика, которая различает окружения в зависимости от целевой ветки:
- Если merge происходит в ветку `main`, то все сущности собираются с префиксом `prd-*`, что соответствует продакшен-окружению.
- При merge в другие ветки, сборка осуществляется с префиксом `dev-*`, что позволяет поддерживать стабильную рабочую версию при одновременной активной разработке новых функций.

Данный подход обеспечивает возможность параллельного ведения разработки и поддержания рабочего продакшен-окружения.

Подробное описание процесса и конфигурация пайплайна доступны по [ссылке на GitHub Action](https://github.com/mdan2000/hse_ai_dota2_match_forecast/blob/dev/feature/service/.github/workflows/deploy_lambda_after_pr.yml).
